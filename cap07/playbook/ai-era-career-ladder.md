# AI-Era Engineering Career Ladder

## Level Overview

| Level | Title | Core Value | Judgment Scope | AI-Era Focus |
|---|---|---|---|---|
| L1 | Junior Engineer | Learning and contributing | Code correctness | Building foundations alongside AI |
| L2 | Engineer | Independent delivery | Implementation decisions | Effective AI leverage with understanding |
| L3 | Mid-Level Engineer | Reliable ownership | Approach appropriateness | Specification quality + review rigor |
| L4 | Senior Engineer | Technical leadership | Design soundness | Architecture + review leadership |
| L5 | Staff Engineer | Organizational impact | Directional rightness | Technical strategy + force multiplication |

---

## L1 — Junior Engineer

### Technical Skills
- Writes working code in the team's primary language (with and without AI tools)
- Understands fundamental data structures, algorithms, and design patterns
- Can read and understand code written by others (human or agent-generated)
- Uses version control, CI/CD, and team development tools effectively

### AI-Era Competencies
- Uses AI tools to accelerate learning and delivery
- Can explain code generated by AI agents — not just that it works, but why it works
- Writes basic task specifications with guidance
- Participates in code review, learning to identify common issues

### Judgment
- Identifies obvious bugs and explains reasoning
- Asks good questions about architecture, design, and edge cases
- Knows when to ask for help vs. when to try independently

### Growth Signals
- Demonstrates increasing understanding of systems, not just features
- Progressively catches more issues in code review
- Shows curiosity about how things work, not just how to make them work

---

## L2 — Engineer

### Technical Skills
- Delivers features independently with minimal guidance
- Debugs production issues in familiar systems
- Writes comprehensive tests including edge cases
- Understands the team's domain and system architecture

### AI-Era Competencies
- Consistently writes specifications that produce correct agent output
- Reviews agent-generated code and catches non-trivial issues
- Makes sound decisions about when to delegate to agents vs. write code directly
- Contributes to team discussions about AI-assisted development practices

### Judgment
- Evaluates tradeoffs between different implementations
- Assesses whether agent-generated approaches are appropriate
- Identifies when a task is under-specified before agent delegation

### Growth Signals
- Specification rejection rate declining over time
- Increasing independence in handling ambiguous tasks
- Starting to influence teammates' practices

### Promotion Criteria (L2 to L3)
- [ ] Consistently produces specifications that succeed on first agent attempt
- [ ] Catches non-trivial issues in code review regularly
- [ ] Debugs agent-generated code independently
- [ ] Demonstrates understanding of the systems they work on

---

## L3 — Mid-Level Engineer

### Technical Skills
- Owns complex features end-to-end (design through production)
- Contributes to architectural discussions with informed opinions
- Debugs complex production issues across multiple services
- Writes code that is maintainable, well-tested, and performant

### AI-Era Competencies
- Writes high-quality specifications that consistently produce correct, clean agent output
- Reviews agent-generated code rigorously, catching architectural and security issues
- Identifies systemic patterns in agent output quality and proposes improvements
- Helps teammates improve their specification and review practices

### Judgment
- Evaluates approaches considering maintainability, performance, and team context
- Makes sound technical decisions with incomplete information
- Assesses the long-term implications of technical choices

### Growth Signals
- Recognized by peers as a reliable reviewer
- Influence extending beyond assigned tasks to team practices
- Taking on increasingly ambiguous and complex work

### Promotion Criteria (L3 to L4)
- [ ] Makes architectural decisions that prove sound over time
- [ ] Sets review standards that the team follows
- [ ] Identifies systemic quality issues, not just point bugs
- [ ] Mentors junior engineers effectively in AI-assisted development
- [ ] Influences team practices and workflows

---

## L4 — Senior Engineer

### Technical Skills
- Designs systems that are correct, maintainable, scalable, and secure
- Makes architecture decisions that account for organizational constraints
- Debugs the most complex production issues across the full stack
- Deep expertise in at least one technical domain

### AI-Era Competencies
- Sets the review standards and culture for the team
- Evaluates when agent-generated approaches create technical risk
- Designs systems that work well with human-agent collaboration patterns
- Creates specification templates and review checklists that improve team effectiveness

### Judgment
- Assesses architectural decisions and predicts failure modes
- Evaluates the long-term implications of technical choices across systems
- Makes sound decisions under significant uncertainty
- Balances technical idealism with practical constraints

### Growth Signals
- Technical decisions widely adopted by the team
- Recognized beyond the team as a technical authority
- Creating leverage for others through frameworks and standards

### Promotion Criteria (L4 to L5)
- [ ] Operates across team boundaries on significant technical problems
- [ ] Creates technical strategy that affects multiple teams
- [ ] Develops frameworks and patterns that amplify organizational capability
- [ ] Recognized as a technical leader beyond the immediate team
- [ ] Identifies and drives step-function improvements

---

## L5 — Staff Engineer

### Technical Skills
- Designs systems and architectures that span multiple teams and domains
- Sets technical direction that shapes the organization's trajectory
- Resolves the most ambiguous and highest-impact technical challenges
- Maintains deep expertise while expanding breadth across the stack

### AI-Era Competencies
- Shapes technical strategy for how AI tools and practices are used organization-wide
- Creates the frameworks that define effective human-agent collaboration
- Evaluates emerging AI capabilities and their organizational implications
- Develops the career ladders, review standards, and development programs for AI-native teams

### Judgment
- Evaluates organizational technical strategy and its business implications
- Makes decisions that balance technical, business, and people considerations
- Assesses multi-year technology bets and their risks
- Navigates organizational dynamics to drive technical change

## Junior Engineer Development Program

### Foundation Sprint (Once per quarter)

**Objective:** Build foundational understanding through direct coding practice.

**Duration:** One sprint (two weeks)

**Structure:**
- Selected tasks completed without AI tool assistance
- Pair programming with senior engineers (AI tools allowed for the senior to explain)
- Daily 15-min reflection on what was learned

**Tasks (examples):**
- Implement a feature that involves direct database interaction
- Debug a production issue using logs and metrics
- Write a comprehensive test suite for an existing untested module

### Specification Practice (Ongoing)

- [ ] All tasks require a written specification before agent engagement
- [ ] Specification quality is reviewed by senior engineer weekly
- [ ] Quarterly review of specification rejection rate (target: declining)

### Review Apprenticeship (First 6 months)

- [ ] Shadow senior engineers during code reviews (2x/week)
- [ ] Independent review with comparison to senior's review (2x/week after month 2)
- [ ] Solo review responsibility for low-risk PRs (after month 4)
- [ ] Tracked review quality improvement over time
